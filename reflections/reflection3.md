# Reflection #3

Pod Members: Dylan, Emmanuel, Semir

## Reflection Questions

* Name at least one successful thing this week.

We added the ability for users to search for other users and use their information to prepopulate the form. This was exciting since this removed the issue we had with user fatigue when filling out the create itinerary form, but challenging since it really required us to think about how we wanted this to look like on the backend and frontend (i.e. how should the user store their products and how do we consider the privacy of user information) and integrate this into our website.

* What were some challenges you and/or your group faced this week?

Our first challenge was deploying the website. While our program worked locally, when we put the application on Render, we found that our features oftentimes did not work, sometimes being attributed to issues like missing an API key. Another challenge we faced this week was improving the user experience since, while we were nearly done with the user features we implemented, we were experimenting with user scenarios end-to-end and found small bugs (i.e. UI for the loading screen having an outdated NavBar, cases where liking itineraries were not reflected on the frontend). Finally, our team struggled with creating the right demo flow in preparation for our demo this week and next week. Since we implemented multiple features, it was hard to consolidate these features in a cohesive presentation that could fit in the time frame we were given. However, by regularly practicing and cutting parts of our presentation, we were able to create a demo presentation that we are proud of.

* Did you finish all of your tasks in your sprint plan for this week? If you did not finish all of the planned tasks, how would you prioritize the remaining tasks on your list?  (i.e over planned, did not know how to implement certain features, miscommunication from the team, had to pivot from original plans, etc.)

We finished nearly all of the features we wanted to create, including the ability to search for users, integrating Google authentication, exporting itinerary through email + clipboard, and the ability to edit itineraries. We however did not implement our two stretch features which included the ability to edit itineraries through an AI chatbot, giving users to ability to provide custom tags, and finally giving users to provide custom locations. This mainly was since we were very ambitious with all of our features and overplanned, especially because we were assisted with AI. Ultimately, we decided to focus more so on the user experience and having a complete app rather than rushing out features when at the end of the week. This pivot mid-week allowed us to ultimately finish our MVP so we are prepared for our final presentation.

* Did the resources provided to you help prepare you in planning and executing your capstone project sprint this week? Be specific, what resources did you find particularly helpful or which tasks did you need more support on?

We very much appreciated the Bug Bash because we got to see how other users experienced our app and how we could improve the app accordingly. Through our feedback, we were able to change our user experience so the application was more cohesive and we were able to account for more edge cases (i.e. if the user forgot their password while logging in). We also appreciated the support we got from our advisors, managers, and mentors since they helped us consider each user scenarios and consider how we can approach the final MVP features we planned on implementing including Google authentication and the user search feature. 

* Which features and user stories would you consider “at risk”? How will you change your plan if those items remain “at risk”?
Since this is the last Sprint, we have nearly finished all of the features and user stories. While we had to cut certain features for the sake of the time, including AI-assisted editing of the itinerary and user-generated itinerary stops, we ultimately finished the functionality for all the features we planned on completing. For these cut features, they were originally "at risk" which is why we decided to cut them in the first place.
